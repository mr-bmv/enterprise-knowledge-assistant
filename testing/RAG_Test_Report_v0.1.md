# 2. Цель тестирования

Проверить корректность работы RAG-пайплайна:

- загрузка корпоративного документа;
- сегментация документа;
- создание embedding;
- поиск релевантных чанков;
- генерация ответа LLM на основании найденного контекста.

Основная задача:

Обеспечить получение AI Assistant корректных ответов исключительно на основании корпоративной базы знаний.


---

# 3. Первоначальная проблема

При первоначальном тестировании AI Assistant демонстрировал нестабильные результаты.

Пример проблемы:

Вопрос:

"Кто должен согласовать командировку стоимостью 100 000 рублей?"

Ожидаемый результат:

- Непосредственный руководитель;
- Финансовый директор.

Фактический результат:

AI Assistant не находил необходимую информацию, хотя данные присутствовали в документе.


---

# 4. Исследование вариантов хранения знаний

Были проверены различные форматы представления корпоративного документа.


## 4.1 PDF версия

Файл:

Reglament_Komandirovki_Demo_v1.1.pdf


Настройки:

Chunk size:
1024

Overlap:
50

Separator:
\n


Результат:

Количество чанков:
69


Проблема:

Некоторые смысловые блоки разделялись.

Пример:

Отдельно находились:

- название правила;
- вопрос;
- часть ответа.


Вывод:

Формат PDF без дополнительной подготовки недостаточно эффективен для RAG.

## 4.3 TXT версия с FAQ структурой

Файл:

Настройки:

Chunk size:
2000

Overlap:
250

Separator:
\n


Результат:

Количество чанков:
134


Проблема:

Разделитель по символу новой строки создавал слишком маленькие смысловые блоки.


Пример:

Отдельные чанки:

- Вопрос;
- Ответ;
- Категория.


Вывод:

Необходимо изменить стратегию сегментации.


---

# 5. Найденная причина проблемы

Основная причина: 

Неверная стратегия chunking.


Использование разделителя: `\n`


приводило к разбиению текста по каждой строке.


Результат:

Смысловой блок:
Правило
Ответ
Контекст


становился несколькими независимыми чанками.


---

# 6. Решение

Была изменена стратегия подготовки базы знаний.


## Изменения:

### 1. Формат документа

Использован TXT формат.


### 2. Структура знаний

Вместо FAQ использованы атомарные бизнес-факты.


Пример:

Было:

Вопрос:
Какой лимит гостиницы?

Ответ:
150 USD

Стало:
Максимальный лимит компенсации гостиницы
при зарубежной командировке составляет
150 USD в сутки.



### 3. Настройки сегментации

Separator: `\n\n`

Chunk size: `2000`



Overlap: `250`



Top K: `5`

# 8. Выводы

В процессе тестирования установлено:

1. Качество RAG зависит не только от модели LLM и embedding.

2. Подготовка базы знаний является критическим этапом.

3. Некорректная сегментация приводит к потере бизнес-контекста.

4. Для корпоративных документов рекомендуется использовать:

- атомарные бизнес-факты;
- логические смысловые блоки;
- контролируемую сегментацию.

## 1. Назначение документа

Настоящий документ определяет цели, границы, требования и критерии успешности проекта Enterprise Knowledge Assistant.

Паспорт проекта является основным документом этапа Discovery и используется в качестве отправной точки при проектировании архитектуры решения, разработке AI-компонентов и планировании последующих этапов реализации.

## 2. Описание проекта

Enterprise Knowledge Assistant — корпоративный AI-ассистент, предназначенный для поиска информации в нормативной документации компании и предоставления сотрудникам точных ответов на основании утвержденных внутренних документов.

Ассистент использует архитектуру Retrieval-Augmented Generation (RAG) и отвечает исключительно на основе корпоративной базы знаний без обращения к открытым источникам информации.

Проект реализуется в виде MVP с последующим развитием до полноценной корпоративной AI-платформы.

## 3. Бизнес-проблема

В крупных производственных компаниях сотрудники регулярно обращаются в HR, отдел закупок и другие подразделения с типовыми вопросами:

- как оформить командировку;
- какие существуют лимиты расходов;
- как согласовать закупку;
- какие документы необходимо предоставить;
- где найти действующий регламент.

Большая часть подобных обращений связана с поиском информации, уже содержащейся во внутренних документах компании.

Это приводит к:

- увеличению нагрузки на профильные подразделения;
- потере рабочего времени сотрудников;
- получению противоречивых консультаций;
- увеличению времени поиска необходимой информации.

## 4. Цель проекта

Создать корпоративного AI-ассистента, который предоставляет сотрудникам быстрые, достоверные и единообразные ответы на основе утвержденной внутренней документации компании.

## 5. Бизнес-цели

Проект направлен на достижение следующих целей:

- сокращение времени поиска корпоративной информации;
- снижение количества типовых обращений в HR и смежные подразделения;
- обеспечение единообразной трактовки внутренних регламентов;
- демонстрация применения современных AI-технологий в корпоративной среде;
- создание масштабируемой архитектуры для последующего расширения функциональности.

## 8. Область проекта (Scope)

### В рамках MVP
Система должна:
- отвечать на вопросы сотрудников по внутренним документам;
- использовать только корпоративную базу знаний;
- поддерживать русский и английский языки;
- сохранять историю диалогов;
- поддерживать загрузку документов форматов PDF, DOCX, TXT и Markdown;
- сообщать пользователю об отсутствии информации в базе знаний.

### Вне рамок MVP
На первом этапе система не должна:
- искать информацию в Интернете;
- отвечать на вопросы общего характера;
- принимать кадровые решения;
- консультировать по юридическим вопросам;
- заменять сотрудников HR;
- генерировать ответы при отсутствии подтверждающей информации в документах.

## 9. Функциональные требования

**FR-01**  
Ответы формируются исключительно на основании корпоративной документации.

**FR-02**  
Для поиска информации используется механизм Retrieval-Augmented Generation (RAG).

**FR-03**  
Поддерживаются русский и английский языки.

**FR-04**  
При отсутствии информации система сообщает пользователю об этом и не генерирует предположений.

**FR-05**  
Поддерживается работа со следующими форматами документов:
- PDF
- DOCX
- TXT
- Markdown

**FR-06**  
Ведется журнал всех пользовательских диалогов.

## 10. Нефункциональные требования

### Производительность
Среднее время формирования ответа не должно превышать 5 секунд для типовых запросов.

### Масштабируемость
Архитектура должна обеспечивать возможность подключения:
- новых баз знаний;
- дополнительных подразделений;
- внешних сервисов;
- новых языковых моделей.

### Надежность
Ответы должны основываться исключительно на подтвержденных данных из базы знаний.

### Объяснимость
Каждый ответ должен иметь возможность быть сопоставленным с соответствующим фрагментом документа.

### Безопасность
Система не должна раскрывать информацию, отсутствующую в корпоративной документации.

## 11. Требования к AI-системе

AI-ассистент обязан:
- использовать Retrieval-Augmented Generation (RAG);
- предотвращать галлюцинации модели;
- работать только с корпоративной базой знаний;
- поддерживать многоязычный диалог;
- учитывать историю переписки пользователя.

## 12. Ограничения проекта

На текущем этапе разработки принимаются следующие ограничения:
- используются только бесплатные AI-сервисы и тарифные планы;
- платформа разработки — Dify;
- основная языковая модель — Gemini 3.6 Flash;
- собственная серверная разработка в рамках MVP не предусматривается;
- используются исключительно тестовые корпоративные документы.

## 14. Критерии успешности проекта

Проект считается успешно реализованным, если:
- AI-ассистент отвечает на вопросы на основании корпоративной документации;
- отсутствуют случаи генерации неподтвержденной информации;
- пользователь получает понятное сообщение при отсутствии ответа в базе знаний;
- система поддерживает двуязычное взаимодействие;
- архитектура допускает дальнейшее развитие без существенной переработки.

## 17. Архитектурные принципы

При разработке проекта используются следующие принципы:
- AI не генерирует информацию, отсутствующую в корпоративной базе знаний.
- Бизнес-логика по возможности выносится за пределы языковой модели.
- Архитектура проектируется модульной и расширяемой.
- Безопасность и достоверность имеют приоритет над полнотой ответа.
- Каждое архитектурное решение должно быть документировано и обосновано.

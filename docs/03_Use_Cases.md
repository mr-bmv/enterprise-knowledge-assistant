## 1. Назначение документа 

Настоящий документ описывает основные сценарии взаимодействия пользователей с системой **Enterprise Knowledge Assistant**.

 

Документ определяет: 

-  участников системы; 
-  пользовательские сценарии; 
-  ожидаемое поведение AI-ассистента; 
-  источники данных; 
-  ограничения; 
-  требования к будущей реализации. 

 

Use Cases являются основой для: 

-  проектирования AI Workflow; 
-  разработки System Prompt; 
-  создания Intent Map; 
-  подготовки тестовых сценариев; 
-  настройки RAG и Tool Calling.  

---

 

## 2. Акторы системы

 

### 2.1 Сотрудник компании (Employee) 

Основной пользователь системы. 

Использует AI-ассистента для: 

-  получения информации; 
-  поиска корпоративных правил; 
-  уточнения требований документов.  

---

 

### 2.2 HR-специалист 

Получатель сложных обращений. 

В будущих версиях: 

-  принимает эскалированные вопросы; 
-  получает информацию о проблемных диалогах.  

---

 

### 2.3 AI Assistant 

Основной программный компонент. 

Ответственность: 

-  анализ пользовательского запроса; 
-  определение намерения; 
-  поиск информации; 
-  формирование ответа; 
-  применение ограничений.  

---

 

### 2.4 Knowledge Base 

Источник корпоративных знаний. 

Содержит: 

-  регламенты; 
-  инструкции; 
-  политики компании.  

---

## 4. MVP Use Cases

 

 

### UC-001 

Получение ответа по корпоративному документу

#### Цель 

Предоставить сотруднику точный ответ на вопрос на основании утвержденных корпоративных документов. 

---

 

#### Актер 

Employee 

---

 

#### Предусловия 

-  Пользователь имеет доступ к AI Assistant. 
-  В Knowledge Base загружены необходимые документы.  

---

 

#### Основной сценарий

 

| Шаг | Действие |
|----|----|
| 1 | Пользователь задает вопрос |
| 2 | AI анализирует запрос |
| 3 | Определяется намерение пользователя |
| 4 | Выполняется поиск в Knowledge Base |
| 5 | Извлекаются релевантные фрагменты документов |
| 6 | LLM формирует ответ |
| 7 | Пользователь получает ответ |

 

---

 

#### Пример

 

Пользователь: 

> Какой лимит гостиницы при командировке за рубеж? 

---

 

Система:

> Согласно регламенту оформления командировок, лимит гостиницы для зарубежных командировок составляет 150 USD в сутки. 

---

 

#### AI Behavior 

| Параметр | Значение |
|----|----|
| Intent | Corporate Policy Question |
| Источник | Knowledge Base |
| Используется RAG | Да |
| Tool Calling | Нет |
| Риск | Низкий |

 

---

 

### UC-002 

Ответ при отсутствии информации 

#### Цель

 

Предотвращение генерации недостоверных ответов.

 

---

 

#### Актер

 

Employee

 

---

 

#### Основной сценарий

 

| Шаг | Действие |
|----|----|
| 1 | Пользователь задает вопрос |
| 2 | AI выполняет поиск |
| 3 | Релевантная информация не найдена |
| 4 | AI сообщает об отсутствии данных |

 

---

 

#### Пример

 

Пользователь:

 

> Компания оплачивает аренду яхты во время командировки?

 

---

 

Ответ:

 

> В доступных корпоративных документах отсутствует информация по данному вопросу.

 

---

 

#### AI Behavior

 

| Параметр | Значение |
|----|----|
| Intent | Unknown Corporate Policy |
| Источник | Нет |
| Генерация предположений | Запрещена |
| Fallback | Да |

 

---

 

### UC-003

 

Ответ на английском языке

 

#### Цель

 

Обеспечить поддержку международной компании.

 

---

 

#### Основной сценарий

 

Пользователь:

 

> What is the daily allowance for international business trips?

 

---

 

Система:

 

Определяет язык запроса → выполняет поиск → формирует ответ на английском.

 

---

 

#### AI Behavior

 

| Параметр | Значение |
|----|----|
| Language Detection | Automatic |
| Knowledge Source | RU/EN documents |
| Response Language | User language |

 

---

 

### UC-004

 

Контекстный диалог

 

#### Цель

 

Обеспечить продолжение разговора без повторного ввода контекста.

 

---

 

#### Пример

 

Пользователь:

 

> Какой лимит гостиницы в командировке?

 

AI:

 

> 7000 рублей по РФ, 150 USD за рубежом.

 

Пользователь:

 

> А если поездка в Германию?

 

AI:

 

> Для зарубежной командировки применяется лимит 150 USD в сутки.

 

---

 

#### AI Behavior

 

| Параметр | Значение |
|----|----|
| Conversation Memory | Да |
| Context Window | Да |
| Источник ответа | История + Knowledge Base |

 

---

 

### UC-005

 

Вопрос, требующий нескольких документов

 

#### Цель

 

Проверить способность системы работать с несколькими источниками знаний.

 

---

 

#### Пример

 

Пользователь:

 

> Можно ли купить ноутбук за 120 000 рублей во время командировки?

 

---

 

Система должна:

 

1.  Определить, что вопрос связан с закупкой. 
2.  Найти правила закупок. 
3.  При необходимости учесть правила командировок. 
4.  Сформировать объединенный ответ. 

 

---

 

#### AI Behavior

 

| Параметр | Значение |
|----|----|
| Intent | Multiple Policy Query |
| Documents | Multiple |
| Retrieval | Multiple chunks |

## 7. Архитектурные последствия

 

На основании Use Cases принимаются следующие решения:

 

1.  Система должна иметь механизм определения пользовательского намерения. 
2.  RAG является основным механизмом получения корпоративных знаний. 
3.  Ответы без подтверждения источником запрещены. 
4.  Для будущих бизнес-операций потребуется отдельный слой Workflow/API. 
5.  AI-модель не должна напрямую изменять данные корпоративных систем. 
6.  Будущая архитектура должна поддерживать расширение через новые Capabilities.
